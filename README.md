# Gaussian Ray Tracing for HDRP

A Unity Package Manager package for rendering 3D Gaussian splats and registered triangle meshes together using hardware ray tracing in HDRP, with mesh transmission, lighting and shadows. Use it with **any 3D Gaussian splatting object or scene in the supported input format**: everyday objects, plants, furniture, vehicles, buildings, captured environments or anatomical models. No specimen or anatomy-specific data is required. Combine your splats with conventional Unity geometry such as glass, display surfaces, interactive objects or explanatory meshes.

**Optional semantic labels make individual parts of an object or scene controllable.** Each Gaussian can carry a label you define, such as `Chair`, `Wall`, `Wheel`, `Petals` or `Leaves`. Keep a selected part visible while fading its surroundings, isolate a class, or create a movable cutaway that affects only chosen labels. Labels describe content; asset layers independently group splats for rendering. Unlabeled Gaussian models can be imported and rendered too.

The package includes tools to import existing Gaussian PLY models, bake semantic labels from aligned scene geometry, or import labels generated by an external workflow. It does not train Gaussian models from photographs or automatically recognize/segment their contents. See [Semantic Gaussians: authoring and use](#semantic-gaussians-authoring-and-use) for a complete workflow.

Package: `com.markus.gaussian-raytracing` version `0.1.0`.

## Requirements and status

Target configuration: **Unity 6000.3.12f1, HDRP 17.3.0, Windows x64, Direct3D 12 and a hardware ray-tracing-capable GPU**.

This is an experimental release. Full clean-project rendering and standalone player validation are pending; see [validation status](Documentation~/Validation.md) and [known limits](#limits).

## Example applications

| Content | Example semantic labels | Possible interaction |
| --- | --- | --- |
| Captured room | Chair, Table, Wall | Isolate furniture or fade walls to inspect the layout. |
| Vehicle or product | Body, Wheels, Interior | Focus on one component or fade the exterior to reveal captured interior detail. |
| Plant or flower | Petals, Leaves, Container | Highlight petals while retaining the surrounding plant as context. |
| Building or outdoor scene | Facade, Roof, Vegetation | Inspect architectural features while reducing visual obstruction. |
| Anatomical model | Bone, Vessels, Soft tissue | Explore labeled structures for teaching or visualization. |

These are examples of user-defined labels, not built-in categories or automatic recognition. The same tools work with other objects and class names. Revealing a hidden part requires that part to already exist in the Gaussian data or accompanying meshes.

## Install

1. Clone this repository or download and extract its ZIP, then open a compatible HDRP project.
2. In **Window > Package Manager**, choose **Install package from disk** (or **Add package from disk**) and select this repository's `package.json`.
3. Open **Tools > Gaussian Ray Tracing > Setup and Diagnostics**.
4. Configure Windows DX12 and restart Unity if the Editor is using another graphics API. Enable Custom Pass and Ray Tracing on the active HDRP asset using the setup window.

Installing this package into a URP project does not convert that project's pipeline. Start with HDRP or configure an HDRP pipeline asset first. Package Manager resolves the dependencies declared in `package.json`.

For a Built-in 3D project, open **Window > Rendering > HDRP Wizard** and fix the HDRP configuration, including creating/assigning the pipeline asset. Then enable Custom Pass and Ray Tracing through this package's setup window. Unity's "current HDRP asset does not support Custom Passes" message can also mean **no HDRP asset is assigned**. Sample creation checks these prerequisites before modifying scenes.

This fork **replaces** `org.nesnausk.gaussian-splatting`. Remove the upstream package before installation: assemblies, types, shader names and GUIDs are intentionally preserved for migration and cannot coexist. Do not copy the package into Assets as well as installing it with Package Manager.

## Try the sample

1. Select this package in Package Manager and import **Basic Hybrid Scene** from its Samples section.
2. Choose **Tools > Gaussian Ray Tracing > Samples > Create Basic Hybrid Scene**.
3. The builder creates a fresh scene and materials under a unique `Assets/3DGRT Basic Hybrid Scene` folder. It asks Unity to save modified scenes before opening the new one. Repeating it creates a new output folder and does not overwrite an earlier example.
4. Complete any platform/HDRP setup reported by **Setup and Diagnostics**, open **Game** view at full resolution, and enter Play Mode.

The scene contains 512 synthetic colored Gaussians, a glass mesh, an opaque receiver, one explicitly assigned point light and an occluder that moves and deforms. It demonstrates Gaussian/mesh composition, transmission through glass, and a moving shadow on the receiver. The sample data are generated mathematically; no external model download is required.

The sample includes a scene builder and a Gaussian asset with its binary data files. See the [sample README](Samples~/BasicHybridScene/README.md) for details.

## Use your own content

1. Convert a Gaussian PLY using **Tools > Gaussian Splats > Create GaussianSplatAsset**. Keep the resulting asset and its adjacent data files together.
2. In Setup and Diagnostics, assign that asset and click **Create Gaussian renderer**. The utility assigns the required shader resources, enables all asset layers, and selects the 3DGRT backend.
3. Select a Game camera and click **Configure camera**. This explicitly enables Custom Pass and disables stereo, dynamic resolution, MSAA and temporal AA.
4. Assign a directional, point or spot light and click **Create / configure global 3DGRT pass**. The pass is created at **AfterPostProcess**. Point and spot lights need explicit assignment; automatic fallback looks for a directional light.
5. Select mesh objects and assign a material using **Gaussian Splatting/3DGRT Transmission**. Click **Register selected meshes and assign material** to add the registration component and replace their material slots. Set Transmission to `0` for an opaque receiver, or increase it for glass. These edits support Undo; any newly created material remains as an asset.

The renderer traces its own acceleration structure. Ordinary HDRP/Lit objects do not automatically participate in its reflection, transmission or shadow rays. Participating meshes require `MeshFilter`, `MeshRenderer`, `Gaussian3DGRTTransmission` and a compatible material pass.

The importer accepts uncompressed **binary little-endian Gaussian PLY** with float32 Gaussian properties, including standard 248-byte records and extended layouts with an additional layer. Properties are mapped by name, so Scaniverse-style ordering and omitted normals also work. Missing layers become layer 0; present layers must be integers in 0-255. Missing higher-order SH is zero-filled for degree 0-2 models. ASCII, big-endian, compressed PLY, ordinary point clouds and mesh PLY need conversion/export to the supported Gaussian format first. Compatibility depends on the file's Gaussian properties, not the subject it depicts.

For meshes whose vertices or indices change in place, use `RayTracingMode.DynamicGeometry` and call `Gaussian3DGRTTransmission.MarkGeometryDirty()` after the change. The sample demonstrates this explicitly. `Mesh.MarkDynamic()` alone is insufficient.

## Semantic Gaussians: authoring and use

### What the labels represent

A semantic Gaussian is a regular Gaussian with an additional unsigned 32-bit class ID. For example, a room could use `1 = Chair`, `2 = Table`, `3 = Wall`; a flower could instead use `1 = Petals`, `2 = Leaves`, `3 = Container`. You define the meaning of the IDs for your data. ID `0` means undefined/unassigned. Each labeled splat has one ID, so this is a discrete classification rather than a set of probabilities or a language embedding.

Two assets work together:

- **Semantic sidecars** (`*_sem.bytes`) store one ID per Gaussian for each imported asset layer.
- A **Semantic Label Table** (`GaussianSplatSemanticLabelTable`) maps IDs to readable names for the inspector and application UI. Creating a table alone does not assign labels to any Gaussians.

Semantic IDs are independent of the PLY `layer` property. Layers use IDs in 0-255 and partition the imported data; semantic classes can distinguish multiple structures within a layer and can be shared across layers.

### Bake labels from scene geometry

Use this route when you have segmentation meshes or manually authored collider regions aligned with an existing splat object or scene. The walkthrough uses a flower with separate regions for petals, leaves and its container; the same steps apply to furniture in a room, components of a product, or any other classes you define.

1. Import your Gaussian model and create its renderer as described under **Use your own content**. Keep the generated asset and binary files in a writable project folder, such as `Assets/Gaussians`.
2. Align the segmentation geometry with the Gaussian renderer in the scene. Create a parent such as `FlowerSegments`, with one direct child group per class: `Petals`, `Leaves`, `Container`. Each group's descendant geometry belongs to that class. Avoid putting every class under one additional child group, because that would merge them into one semantic source.
3. Open **Tools > Gaussian Splats > Bake Semantic Sidecars**, or click **Open Semantic Baker** in the Gaussian renderer inspector. Assign **Renderer** and **Segmentation Root**.
4. Keep **Auto Temp Colliders** enabled to generate temporary convex MeshColliders for source meshes that do not already have colliders. Alternatively, provide enabled colliders yourself. Keep source objects active while baking; **Include Inactive** includes objects in source collection but does not make inactive colliders participate in physics queries.
5. Enable **Overwrite Existing** when intentionally replacing previously baked sidecars, then click **Bake Semantic Sidecars**. The tool writes the sidecars next to the position data, attaches them to the Gaussian asset, and creates or updates the renderer's label table. Temporary colliders are removed afterward.
6. Inspect the Console's assigned/unassigned counts, then test the labels using **Semantic Alpha** below. Save the scene to retain the renderer's label-table assignment.

The baker assigns nonzero IDs in source traversal order and derives display names from group names (text after the first dot is removed). Reordering groups or changing which sources participate can change IDs on a later bake; check any application code that stores them.

**Current baking behavior:** classification tests a small sphere at each Gaussian's center against the source colliders; unmatched centers remain ID 0. Despite its name, **Max Distance** currently controls the overlap radius as `max(0.000001, Max Distance * 0.01)`, not a nearest-mesh labeling distance. Convex temporary colliders can fill gaps in concave shapes. Use carefully fitted collider regions for detailed structures, and avoid overlapping classes: the first matching physics overlap wins, with no explicit class priority. Review the result before using it as a semantic reference.

Baking uses the renderer's current transform relative to the segmentation geometry. The saved IDs then stay attached to the Gaussians; moving the renderer does not dynamically reclassify them against the scene. Rebake if you need labels based on a different alignment. All renderers sharing the same Gaussian asset share these per-splat IDs.

### Import labels from an external workflow

Use this route if a segmentation or annotation pipeline already provides a class for every Gaussian. Any image/mesh segmentation must first be mapped to the individual Gaussian records by that external workflow.

1. Prepare a raw binary file containing one little-endian `uint32` ID per input PLY vertex, in **exactly the PLY's vertex order**, with no header. For `N` splats the file must contain `4 * N` bytes. Use 0 for unassigned splats.
2. Optionally prepare a JSON label file, for example:

   ```json
   { "1": "Petals", "2": "Leaves", "3": "Container" }
   ```

   JSON arrays such as `[{"id":1,"label":"Petals"}]` and CSV lines such as `1,Petals` are also supported.
3. Open **Tools > Gaussian Splats > Create GaussianSplatAsset**, select the PLY, and supply **Semantic IDs File** and **Semantic Labels File** before creating the asset. The importer keeps IDs aligned while splitting layers and reordering splats for storage.
4. Assign the generated `<model>_SemanticLabels.asset` to **Semantic Labels** on the Gaussian renderer. Without a label file, create a table via **Assets > Create > Gaussian Splatting > Semantic Label Table**, enter the matching IDs/names, and assign it there.

For an already imported asset with compatible sidecars, use **Tools > Gaussian Splats > Attach Semantic Sidecars**. Choose the **Gaussian Asset**, assign each layer's **Semantic Sidecar** (or use **Auto-Fill From Adjacent _sem.bytes**), optionally supply a label table/file, and click **Attach Semantic Sidecars**. Leave **Clear Unassigned Layers** off to preserve existing bindings for empty slots. The window's **Populate Label Table From Scene Names** only creates names; use the baker to actually classify splats.

**Ordering matters:** attached sidecars must match the target layer's stored Gaussian order and count, including any import padding. A raw file in the original PLY order belongs in the asset creator, not directly in the attacher. Reimporting with different ordering or compression settings can require regenerating sidecars. Distribute the label table and sidecars together with the Gaussian asset and its other data files.

### Use labels for visibility and cutaways

Select the Gaussian renderer and find **Semantic Alpha** in its inspector. Choose a **Semantic Label**, then adjust **Matching Alpha** and **Other Alpha**. These multiply existing opacity; a value of 1 preserves it and 0 hides it.

| Intended view | Selected label | Matching Alpha | Other Alpha |
| --- | --- | --- | --- |
| Emphasize a chair while retaining the room as context | Chair | 1 | 0.15 |
| Show only the petals | Petals | 1 | 0 |
| Fade a vehicle body to reveal captured interior parts | Body | 0.1 | 1 |

The examples require corresponding labels in your own data. Select **None** to disable the inspector's single-label alpha filter. Opacity control does not generate missing geometry or hidden surfaces: those parts must already exist in the Gaussian data or as meshes.

For a localized cutaway, add a **CutoutView** component to a scene GameObject, assign its **Gaussian Renderer**, and position it over the region of interest. Choose **Cylinder** or **Ellipsoid**, set its dimensions, and select the affected labels under **Semantic Filter**. Reduce **Alpha Multiplier** to fade only those classes inside the volume; for example, fade a room's wall within the cutaway while preserving its furniture. An **empty semantic filter affects all classes**. Leave **Replace Alpha With Falloff** disabled for ordinary opacity multiplication; cylinder views also offer **Gaussian Falloff** for a softer radial transition. **Render View Mesh** controls the optional visual representation of the volume.

Application code can drive several labels together through `GaussianSplatRenderer.SetSemanticAlphaLabelIds(...)`, with `m_SemanticMatchAlphaMultiplier` and `m_SemanticNonMatchAlphaMultiplier`. `SetSemanticDimLabelIds(...)` and `m_SemanticDimAlphaMultiplier` provide an additional dimming selection, while `CutoutView.SetSemanticIds(...)` updates a cutaway's class filter. These APIs let you build object- or part-selection menus, guided presentations or interactive inspection tools; the package supplies the rendering controls, while your application supplies the UI and interactions.

## Limits

- The ray path currently requires a mono Game camera, full resolution, no TAA and no MSAA. Scene view is not the RT preview. XR, URP, mobile, WebGL and macOS RT are not supported by this package release.
- Up to eight directional/point/spot lights are supported. Lighting uses custom display-space normalization; it does not reproduce every HDRP lighting feature.
- Output is composed after post processing, which limits HDRP exposure/post-effect integration.
- Gaussian raster fallback is retained. The transmission material has no raster fallback: unsupported RT configuration can make those meshes invisible.
- Mesh registration covers MeshFilter/MeshRenderer triangle meshes, not automatic skinned-mesh integration.
- Stochastic history needs invalidation when visual content changes. External GPU/video texture updates are not all detected automatically.

Use **Tools > Gaussian Ray Tracing > Log Pass State** to inspect the last Game-camera render. See [architecture and troubleshooting](Documentation~/Architecture.md).
